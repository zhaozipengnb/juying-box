## JAR/PY 源支持方案（分期交付）

**前提事实**（已调研确认）：
- JAR 里的 `csp_*` 是 Dalvik 字节码，无法执行——"支持"= 用 JS 重实现通用爬虫类。数据分析：两个订阅里通用类 **AppYs 家族**（csp_AppDrama/AppGet/AppRJ/App99，共 7 站）是最大可成片的家族，其协议 = 苹果CMS「app 插件」`api.php/app/` 接口族（[drpy-node](https://github.com/hjdhnx/drpy-node) 等有 JS 参考实现）；其余 csp_Bili×11、csp_PanWebShare×8 及各独家类是专门爬虫，逐个移植投入产出极低。
- py 源 = drpy/hipy 服务器 HTTP 接口（`api.php/app/` 不同，py 站是 `…/api/v1/vod/xxx.py` 形态），响应大概率 CMS 兼容 JSON，需实测确认。
- 相对路径站（`./drpy_libs/drpy2.min.js` + `./drpy_js/*.js`，TM-TY 2 站）解析后就是真 drpy 站，现有 siteEngine 漏判。
- 代码库侧：HomePage 完全委托 `isSiteSupported`，新类型无需改 UI；cryptoFramework 零引用，ArkTS 加解密需新引入（@kit.CryptoArchitectureKit）；common 层无通用 URL join 工具。

### Task 1: 相对路径解析（地基，先交付）
1. `common` 新增纯函数 `resolveUrl(base, ref)`（手写 WHATWG 语义：`//`、`../`、`./`、query 合并；ArkTS 无全局 URL 对象）+ 单测。
2. `TvboxModels` 新增 `resolveSiteUrls(config, subUrl)`：把各站 api/ext 中 `./`、`../` 开头的相对值对订阅 URL 绝对化（ext 为字符串时处理；object 形态暂不动，其 url 字段均为绝对地址）。
3. `AppState.loadFromUrl` 与 `initFromStore` 在 `decodeConfigContent` 之后调用（两处都做，兼容旧持久化数据）。
4. 效果：TM-TY 的北川影视、策驰影院直接变为可用 drpy 站；全生态相对路径站通用受益。

### Task 2: py 源支持（drpy/hipy 服务器协议）
1. 协议 spike：找活 drpy/hipy server 实测 `/api/v1/vod/xxx.py` 的请求参数与响应形态（curl 即可；找不到活服务器则本地 docker 起 hipy-server 验证）。
2. 按 spike 结论实现：CMS 兼容 → `siteEngine` 增 `py` 分支（type 3 且 api 以 `.py` 结尾）路由到可配置化后的 CmsJsonApi 或薄 PyDriver（复用 `$$$/#/$` 解析）；协议不同 → 独立 PyDriver。
3. 单测 fixture 对齐 CmsJsonApi.test 模式。

### Task 3: AppYs 家族 JS 驱动（覆盖 csp_App*）
1. 先对 ext 里的真实站抓包（AppGet=https://app.95112475.xyz、AppRJ=http://v.rbotv.cn、AppDrama=华谊/苹果）确认 getNav/列表/详情/播放的 endpoint 与加解密细节。
2. 新增 `AppYsDriver`（common，FetchText 注入）：三变体——明文（ext={url}）、AES（dataKey/dataIv）、RSA（publicKey 签名 token）。加解密用 @kit.CryptoArchitectureKit（AES/RSA 均支持）。
3. `siteEngine` 增 `appys` 分支（csp_AppYsV2/csp_AppDrama/csp_AppGet/csp_AppRJ/csp_App99 类名白名单），buildDriver 路由，HomePage 自动放行。
4. 单测 + TM-TY/影视仓 7 站模拟器走查。

### Task 4: 回归与收尾
全量单测、模拟器走查截图、分 Task 提交。

### 明确不做（本期）
独家 csp_ 类（Bili/PanWebShare/Douban/Wogg/libvio/ptt/czjy/wbbb/wojh/gy 等）——每类一个独立爬虫移植项目，保持「暂不支持」标记；后续按需求逐个评估。

### 风险
- AppYs 各站服务器行为差异大：以实际抓包为准，先支持现有订阅中出现的变体。
- py 无活服务器时：按文档协议 + 单测 fixture 兜底，标注实验性。

预估：T1 约半天，T2 半天～1 天，T3 1.5～2 天，T4 半天。
